## G5: saved entities (chunk file version 4)

The user chose per-chunk entity saving. `Engine::create_saved` adds an engine `Saved{owner}` component; `update_owners` moves ownership to the entity's current chunk only while that chunk is active, so an entity outside the active area stays with its last owner rather than being dropped. The engine chains its entity hooks around the physics `ChunkHooks`: release and store encode the owner's entities into `Chunk::entities` (and release destroys them), and activate recreates them and calls `Game::load_entity`. Records carry transform, visual and a game payload of at most 4 KiB; the chunk file appends u16 count, u32 length and the records. Decoding checks the record structure on the worker, and material IDs and payload consumption are checked on the main thread at activation. Dirty detection compares encoded bytes, so a reordering in the dense set can cause a harmless extra write. Please look at whether generated (recipe) entities are needed: today only runtime-created entities are saved, and a game that creates saved entities in `setup` would duplicate them on every load.

## Editor application (step 1)

The user wants a standalone Unity-style editor, not editors inside games. Decisions: Lua for gameplay scripts, JSON text for project files, and the E1 in-game editor (commit `1ab30dd`) is removed from the runtime; only the `Window::observe`/`handle`/`context` accessors stay. Step 1 adds `seed_editor` (under `editor/`): a hub (new project, open, recent list), a dockable workspace (Project files, Console, Project Settings) and a native macOS folder picker. ImGui is now the pinned 1.92.9b docking release and is linked only by the editor. The engine gains a strict JSON reader/writer (`src/io/json.*`) and `replace_file`/`write_text`/`read_text` in storage; `write_blob` now uses `replace_file`, with the same bytes on disk. Worth a look: `project.seed.json` format 1 (`seed_project`, `name`, `game_id`), where `game_id` is a slug plus 8 random hex digits and will become `Game::id` when projects run.

## Editor step 2: project data assets

Materials, input actions, sounds and particle styles can now be data (`src/project/assets.*`, format in `docs/project-format.md`). Validation reuses the registries: `Assets::problems()` registers into scratch registries and collects each failure, so no rule is duplicated. Engine API changes: `ParticleStyle` gains a required unique `name` and `Particles::find_style`; `Actions::add`/`bind` accept a span and `add` now validates bindings before registering (it used to leave a half-added action on a bad binding); `Binding` has `operator==`; `add_engine_actions()` replaces the three inline registrations; `Audio::play(const SoundDesc&)` previews unregistered sounds (the queue already copied parameters, so this is thread-safe); `Game::materials` is optional when `Game::project_assets` is set. The minimal test game now reads its materials from JSON. Code cost in games: about 17 KB for JSON and 40 KB for asset loading; I'd like the export step to replace both with a binary blob for shipped games.

## Editor step 3: scenes

`src/project/scene_file.*` stores scenes as JSON (see `docs/project-format.md`). The editor's Scene view uses the engine `Renderer` through an ImGui draw callback, so the scene sits at the right place in ImGui's draw order without an extra framebuffer. Renderer changes, all no-ops for games: `set_output(x, y)` offsets the final composite; `begin` disables the scissor test a host UI may leave on; `finish` leaves texture unit 0 active. The demo fingerprint still matches. One verify run produced a 2560x1434 window instead of 2560x1440, right after the editor's windowed smoke tests; eight reruns matched, so I recorded it as macOS window placement, not rendering. Also new: defaulted `operator==` on `Vec2` and `WorldPosition`, and `json_float` shared by the asset and scene writers.
Undo is snapshot-based (`editor/history.hpp`): after each finished edit the app offers a copy of {assets, scene, project name}; identical states are ignored, so no widget needs its own undo code. 100 steps, reset when a different scene opens.

## Editor step 4: terrain as data

`src/project/terrain.*`: fields (sums of perlin/fractal/ridged/distance/spot terms, optionally domain-warped) and first-match rules with scatter. `Terrain` compiles an asset against a material registry and is read-only afterwards, so World's workers share it. The generator version is the FNV-1a hash of the settings JSON without `default_seed`. Past 1.1 radii an island skips noise (elevation -1). `Engine` builds the generator from `terrain.json` when `Game::world.terrain` is unset (`tests/data_game.cpp`). The Scene view samples tile centres directly, in blocks of up to 256 tiles when zoomed out (at most about 30,000 sprites), cached with a half-view margin. Limitation: scatter replaces the tile's material, so trees draw as tiles rather than as objects on the ground.
Follow-up (user-approved core layout change): `Tile` gains `std::uint8_t object` (0 none, else material ID + 1) in former padding; a `static_assert` pins the tile at 12 bytes. Terrain scatter now sets the object instead of replacing the ground. Tiles are generated, not saved, so no save format changes; the demo leaves it at 0 and still matches its fingerprint.

## Editor step 5: play mode

`src/project/runner.*` (`seed::run_project`) turns a project folder into a `Game`: the id and name come from `project.seed.json`, the world and materials from assets, the entities from `scenes/main.json` (lights become a runner-local component), and the player is the `Player` entity, else one at `Spawn`, else at the origin. A resumed save starts from `player.delta`. Default move actions are added only when the project lacks them; water and solid tiles block movement. `Scene::create(Transform)` makes transform-only entities. `seed_player` (`player/main.cpp`) is the runtime. The editor's Play spawns it with posix_spawn, pipes its output into the Console, and stops it with SIGTERM, which SDL turns into a quit, so it checkpoints; it is killed after 3 s. Each Play uses a fresh `.seed/play` save. `tests/data_game.cpp` was removed: the runner and `tests/sample_project` replace it. POSIX only for now, which matches the macOS-only decision.
